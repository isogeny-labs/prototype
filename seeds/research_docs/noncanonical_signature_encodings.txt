DEMONSTRATION DOCUMENT — paraphrase prepared for the Isogeny Evidence Lab sample project. It describes a well-known class of issues; consult primary sources before acting.

Several published analyses of Ed25519 deployments note that verifiers differ in how they treat non-canonical or over-long signature encodings. RFC 8032 requires the signature to be exactly 64 bytes and the scalar S to be less than the group order, but wrapper code around libraries such as OpenSSL, libsodium and the Python cryptography package has been observed to truncate, pad or otherwise normalise signatures before verification, which makes a signature with trailing data verify. This is not a forgery of the underlying scheme; the risk is to systems that treat the signature bytes as an identifier, for example replay caches, transaction IDs or audit logs keyed on the signature. The authors recommend rejecting any signature whose length is not exactly 64 bytes and adding malformed-input tests (trailing bytes, truncation, empty input) to the verification test suite.
